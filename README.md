# PoiResize

画像をウィンドウにドラッグ＆ドロップするだけで、
**リサイズ → 余白調整 → 連番リネーム → 保存** を一括で行う Windows デスクトップアプリです。

- インストール不要（exe 1 個をダブルクリックで起動）
- .NET ランタイムの別途インストール不要（自己完結・単一ファイル exe）
- 元ファイルは絶対に上書き・削除しません（必ず新しいファイルとして書き出します）
- 対応環境：Windows 10 / 11（64bit）

---

## ダウンロードと起動

1. GitHub の **Releases** から `PoiResize-vX.Y.Z-win-x64.exe` をダウンロードします。
2. 好きな場所（デスクトップなど）に置いて、ダブルクリックで起動します。

### 初回起動で「Windows によって PC が保護されました」と出たら

この exe にはコード署名がないため、Microsoft Defender SmartScreen の警告が出ることがあります。

1. 青い画面の **「詳細情報」** をクリック
2. 下に出てくる **「実行」** ボタンをクリック

2 回目以降は出ません。
（ダウンロードしたファイルを右クリック →「プロパティ」→ 下の「許可する」にチェック →「OK」でも解除できます）

## 使い方

### 1. 画像を読み込む

- 画像ファイルやフォルダを、ウィンドウにドラッグ＆ドロップします。
  「＋ 画像」「＋ フォルダ」ボタンから選ぶこともできます。
- フォルダを入れたとき、中のサブフォルダも読み込むかは「サブフォルダも読み込む」で切り替えます。
  （過去の出力先である `resized` フォルダは自動的に除外します）
- 対応形式：JPG / PNG / BMP / GIF（1 枚目のみ）/ TIFF / WebP
  - WebP の読み込みには Microsoft Store の「WebP 画像拡張機能」が必要です（Windows 11 は多くの場合導入済み）。
- 一覧にはサムネイル・ファイル名・元サイズ（回転補正後）が表示されます。

### 2. 並べ替え・削除

- **一覧の並び順が、そのまま連番の順番**になります。
- 行をドラッグして移動、または「▲ 上へ」「▼ 下へ」で並べ替えます（Shift / Ctrl で複数選択可）。
- 「名前順」はエクスプローラーと同じ順（img2 → img10）、「日付順」は撮影日（なければ更新日）の古い順です。
- 選択して Delete キー、または「削除」で一覧から外せます（元ファイルは消えません）。

### 3. リサイズ方法を選ぶ

| モード | 動き |
|---|---|
| 枠内に収める | 縦横比を保ったまま、幅×高さの枠に収まるよう縮小 |
| 埋めて切り抜く | 縦横比を保って枠を埋め、はみ出た部分を中央基準で切る |
| 長辺を指定 | 長い方の辺を指定 px に（例：長辺 1200px） |
| 比率で指定 | 元の何 % にするか（例：50%） |
| 指定サイズに引き伸ばす | 縦横比を無視して幅×高さぴったりに |
| リサイズしない | 余白・リネーム・形式変換だけ行う |

- 「拡大しない（元が小さければそのまま）」をオンにすると、小さい画像は拡大されません。
- スマホ写真の回転情報（EXIF Orientation）は自動で反映されるので、横倒しになりません。

### 4. 余白・キャンバス

- **キャンバスのサイズを固定**：例えば 1080×1080 にすると、画像をその中に置き、周りを余白で埋めます。
  画像がキャンバスより大きい場合は収まるよう縮小されます。配置位置は 中央 / 上 / 下 / 左 / 右。
- **余白を付ける**：上下左右一括、または個別に px で指定します。
  - キャンバス固定あり：キャンバスの内側に余白を取り、その内側に画像を収めます。
  - キャンバス固定なし：画像の外側に余白が足されます（画像 800×600 ＋ 余白 20 → 840×640）。
- 余白の色：白 / 黒 / 透明 / カラーコード（`#RRGGBB`）
  - 透明は PNG（と TIFF・WebP）のときだけ。JPG などでは白になります。

### 5. 連番リネーム

パターンに次の記号を書けます。

| 記号 | 意味 | 例 |
|---|---|---|
| `{name}` | 元のファイル名（拡張子なし） | `IMG_0001` |
| `{###}` | 連番。`#` の数が桁数（0 埋め） | `{###}` → `001` |
| `{date}` | 撮影日（EXIF。なければ更新日）を `yyyyMMdd` で | `20240131` |
| `{date:yyyy-MM-dd}` | 日付の書式指定 | `2024-01-31` |

- 例：`{name}_{###}` → `IMG_0001_001.jpg`、`shop_{###}` → `shop_001.jpg`、`{date}_{##}` → `20240131_01.jpg`
- 開始番号と増分を指定できます（開始 10・増分 5 → 010, 015, 020…）。
- 一覧の「→ 新しい名前」「出力サイズ」列に、実行前のプレビューが表示されます。
- 同じ名前になったり、出力先に同名ファイルがあったりした場合は自動で `_1`, `_2` … を付けます（上書きしません）。
- ファイル名に使えない文字（`\ / : * ? " < > |`）は `_` に置き換えます。

### 6. 出力

- 出力先の初期値は「元フォルダ内の `resized` フォルダ」です。「変更…」で好きなフォルダにできます。
- 形式：元と同じ / JPG / PNG / WebP（この PC で使える場合のみ表示）
  - 「元と同じ」の GIF は PNG で保存します（GIF に戻すと 256 色に減色されて劣化するため）。
  - Windows 標準には WebP の**書き出し**機能がないため、通常 WebP 出力は表示されません。
    「元と同じ」の WebP は PNG で保存します。
- JPG 画質：1〜100（初期値 90）
- メタデータ（EXIF）：初期値は **消す**（位置情報が残るのを防ぐため）。
  「残す」にした場合も、引き継げるのは JPG→JPG / TIFF→TIFF のときだけです（回転情報は補正済みなので 1 にリセット）。
- カラープロファイル（Adobe RGB や iPhone の Display P3 など）が埋め込まれた画像は、読み込み時に sRGB に変換するので、メタデータを消しても色が大きく変わりにくくなっています。

### 7. 実行

- 「▶ 実行」で開始。プログレスバーで進み具合が分かり、「キャンセル」で中止できます。
- 複数の画像を並列で処理するので、処理中も画面は固まりません。
- 読めない画像などは飛ばして続け、最後に「成功 ○ 件／失敗 ○ 件」と失敗の理由を表示します。
- 終わったら「📂 出力フォルダを開く」で出力先をエクスプローラーで開けます。

### プリセット・設定の保存

- 「今の設定を保存」で名前を付けて保存、コンボボックスで呼び出し、「削除」で消せます。
- 初回は「メルカリ用」「インスタ正方形」「ブログ用」が入っています（お好みで調整してください）。
- 前回の設定は終了時に自動保存され、次回起動時に復元されます。
- 保存場所：`%APPDATA%\PoiResize\`（`settings.json` / `presets.json`）。消せば初期状態に戻ります。

### バージョンの確認

メニューの「ヘルプ」→「PoiResize について」、またはウィンドウのタイトルに表示されます。

## リリースの手順（開発者向け）

1. GitHub のリポジトリで **Actions** タブを開く
2. 左の一覧から **Release** を選ぶ
3. 右側の **Run workflow** ボタンを押す
4. 「バージョン番号」に `1.0.0` のように入力（`v` は付けなくてよい）
5. 緑の **Run workflow** を押して実行

自動で次のことが行われます。

1. 入力したバージョンをアプリに埋め込んでビルド・テスト
2. 単一ファイル exe（`PoiResize-v1.0.0-win-x64.exe`）を発行し、埋め込まれたバージョンを確認
3. タグ `v1.0.0` を作成
4. GitHub Release を作成して exe を添付

- 同じバージョンのタグ（またはリリース）がすでにあると、ビルド前にエラーで止まります。
- `1.2.0-beta1` のようにハイフン付きにすると「プレリリース」として公開されます。

### CI

push と Pull Request のたびに、`windows-latest` でビルドと全テストが走ります
（Actions の実行結果から、テスト用の exe も 7 日間ダウンロードできます）。

## 開発

### 構成

```
PoiResize/
├─ src/
│  ├─ PoiResize.Core/      net8.0          … OS 非依存のロジック
│  │    Geometry/   … リサイズ後サイズ計算・余白キャンバス配置
│  │    Pixels/     … EXIF 回転補正・Lanczos3 リサイズ・合成
│  │    Naming/     … リネームパターン展開・重複回避・出力計画
│  │    Processing/ … 1 枚の処理パイプライン・並列一括処理
│  │    Persistence/… 設定・プリセットの JSON 保存
│  ├─ PoiResize.Imaging/   net8.0-windows  … WIC での読み込み・書き出し・メタデータ・サムネイル
│  └─ PoiResize.App/       net8.0-windows  … WPF の画面
└─ tests/
   ├─ PoiResize.Core.Tests/     … xUnit（どの OS でも実行可）
   └─ PoiResize.Imaging.Tests/  … xUnit（Windows のみ：実際の JPEG/PNG/GIF で検証）
```

Core は WPF に依存しないので、サイズ計算・配置・リネーム・回転補正・一括処理（偽のコーデックで）を
Windows 以外でもテストできます。

### ビルド・テスト

```
dotnet build PoiResize.sln
dotnet test PoiResize.sln
dotnet publish src/PoiResize.App/PoiResize.App.csproj -c Release -r win-x64 --self-contained true -p:Version=1.0.0 -o publish
```

必要なもの：.NET 8 SDK。アプリの実行と Imaging のテストは Windows が必要です
（Linux/macOS でも `EnableWindowsTargeting` によりビルドと Core のテストは可能）。

### 外部ライブラリについて

**アプリ本体は外部ライブラリを使っていません。** 画像の読み書きは Windows 標準の WIC
（WPF の `System.Windows.Media.Imaging`）、リサイズ（Lanczos3）・回転・合成は Core に自前で実装しています。

自前実装にした理由：WPF 標準の拡大縮小は描画スレッド（STA）が必要で並列処理と相性が悪く、
画質も選びにくいためです。純粋な C# にしたことで、どのスレッドからでも安全に並列実行でき、ユニットテストもできます。

テストでのみ使用しているパッケージ：

| パッケージ | ライセンス | 用途 |
|---|---|---|
| xunit / xunit.runner.visualstudio | Apache 2.0 | ユニットテスト |
| Microsoft.NET.Test.Sdk | MIT | テスト実行 |

### WebP について

WIC の WebP **デコーダ**は「WebP 画像拡張機能」で追加されますが、**エンコーダ**は Windows 標準にありません。
WebP 書き出しのために libwebp（BSD ライセンス）を同梱する方法もありますが、
「MIT / Apache 2.0 系のみ」の方針に合わせて採用していません。
アプリは起動時に WebP エンコーダの有無を調べ、使える環境でだけ WebP 出力を選べるようにしています。
